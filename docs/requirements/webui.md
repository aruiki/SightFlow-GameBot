## 0. 製品定義と決定事項

### 0-1. 製品定義

SightFlow WebUI は、**画面の状態を認識して、決められた座標をクリック／キー入力し、次の画面・次のフローへ進むマクロを GUI で組むツール**である。

```
[画面Aを検出] → [A の (x, y) をクリック] → [画面Bに変わったのを待つ]
      → [B の (x, y) をクリック / キーを押す] → [次の画面へ]
```

### 0-2. 最重要領域（開発リソースの配分）

1. **何でもラベル付けできる YOLO システム**
   - 任意の物体・UI・アイコンを言葉（YOLO-World）または学習（独自YOLO）で検出する。
   - 画面から切り出して箱を描き、ラベルを付け、そのまま学習データにできる。
2. **画面遷移の検出**
   - 今どの画面／状態にいるかを判定し、A→B の遷移を待てる。
   - 画面ごとに「次に何をするか」を定義できる。
3. **画面類似の検出**
   - 基準画面と現在画面の一致度をスコアで出し、しきい値で安定して判定する。
   - 解像度差・アニメ・点滅・部分的変化に耐える。

### 0-3. 行動はシンプルに保つ

- 標準の行動は **クリック（画面座標 x, y）／キーを押す・離す・押し続ける／待つ** のみ。
- マウス照準・ドラッグ・スマートキャスト・模倣学習・地形経路探索は**非目標**（既存実装はレガシーとして互換維持）。
- 複雑な戦術的判断は、検出結果と画面状態を条件にした**分岐**で表現する。

### 0-4. 設計原則

- **検出が失敗した理由を UI で説明できる**こと（スコア、候補、しきい値、ROI、モデル、取り込み）。
- **誤操作を送らない**こと（見るだけでは入力0件、操作するは確認、F12で停止）。
- 画面・ラベル・フローの変更が互いに壊れないこと（参照切れの警告、保存時の検証）。

## 1. 目的と成功指標

### 1-1. 目的

- ユーザーが、対象アプリの画面を登録し、その画面に応じたクリック／キー操作のマクロを作れる。
- 画面遷移と画面類似を、しきい値とスコアで説明可能な形で判定できる。
- 任意の対象を YOLO でラベル付けし、検出精度を継続的に改善できる。

### 1-2. 成功指標

| ID | 指標 | 目標 |
|---|---|---|
| KPI-1 | 初回起動から「1画面を登録し、一致スコアが表示される」まで | 5分以内 |
| KPI-2 | 「画面A → (x,y)クリック → 画面B待ち」マクロの作成 | 15分以内 |
| KPI-3 | 画面類似の判定（同一画面/別画面）の正解率 | 同一画面 95%以上、別画面の誤一致 1%未満 |
| KPI-4 | 検出失敗の原因特定（スコア・候補・設定へ） | 3クリック以内 |
| KPI-5 | 見るだけモード中の入力送出 | 常に0件 |
| KPI-6 | 画面類似1件あたりの判定時間 | 10ms以下（ROI適用時） |
| KPI-7 | 操作の再現性（同じ座標にクリック） | 幅960pxで±2px以内 |

## 2. スコープ

### 2-1. 対象（In）

- 画面の取り込み（ウィンドウ / 画面範囲 / 動画 / 画像 / デモ）
- YOLO による物体検出（YOLO-World / 学習済みYOLO）、色・テンプレート検出
- ラベル付け（アノテーション）、自動ラベル、学習データ出力、学習（P2）

- 認証、ユーザー管理、クラウド同期、複数人同時編集
- モバイル／タッチUI
- 検出器アルゴリズムの研究開発そのもの

## 4. 用語

| 用語 | 意味 |
|---|---|
| 画面（スクリーン / 状態） | アプリが取り得る画面。名前・基準画像・ROI・しきい値を持つ |
| 画面テンプレート | 画面判定に使う基準画像。1画面に複数枚（バリエーション）持てる |
| 類似度 | 現在のフレームが画面テンプレートにどれだけ似ているか（0〜1） |
| 画面遷移 | 画面Aから画面Bへ変わること。待機・タイムアウトを持つ |
| マクロ / フロー | 「画面 → 操作 → 次画面」の並び。ノードまたはステップで表現 |
| ラベル | YOLO が検出するクラス名（例: `enemy`, `start_button`） |
| プロンプト | YOLO-World に与える英語の説明（例: `red health bar`） |
| アノテーション | 画面に箱を描いてラベルを付ける作業。学習データになる |
| ROI | 画面・検出の対象範囲。時計やエフェクトなど変動部分を除外する |
| 追跡ID | 同じ物体に付き続ける番号（`#3`） |
| クリック座標 | 画面に対する位置。正規化（0〜1）とピクセルの両対応 |
| ティック | 1フレーム分の「取得 → 認識 → 判断 → 入力」 |
| レガシー操作 | 照準・ドラッグ・模倣など、本版の非目標ノード |

## 5. 前提・制約

- ローカル1プロセス、既定 `127.0.0.1:8765`、認証なし（**ループバック限定**）。
- ブラウザは Chrome / Edge 最新版。`webui/dist` を FastAPI が配信する。
- 対応OSは Windows 10/11（取り込み・入力）。他OSは縮退動作。
- Python 3.10 以上。GPU は任意。
- 1プロセス1プロジェクト。プロジェクトは JSON 1ファイル。
- リアルタイム表示は WebSocket + JPEG（品質72、長辺1280px上限）。
- 既定フレームレートは 15〜20fps。解析は取得フレームに対して行う。
- 画面類似は「基準画像 vs 現在フレーム」の比較を基本とする（テンプレートキャッシュ必須）。
- オンラインゲームの自動操作は規約違反になり得る。操作開始前に警告する。
- Ultralytics は AGPL-3.0。配布時にライセンス条件を明示する。

### 6-4. 操作（クリックとキーだけ）

| ID | 要件 | 優先度 | 受入基準 |
|---|---|---|---|

## 7. 画面要件

### 7-1. レイアウト

- ヘッダー + 3ペイン（左: パレット、中央: フロー/キャンバス、右: ライブ・検出・画面・設定）。
- 右パネルは **「ライブ」「検出」「画面」「設定」** の4タブ。
  - **検出**: モデル、ラベル、推論設定、ROI/後処理、統計、スナップショット、アノテーション（P2）
  - **画面**: 画面一覧（サムネイル・スコア）、しきい値、テンプレート、ROI、遷移テスト
- 中央は「状態フロー」ビューを既定とし、必要なら「詳細ノード」ビューへ切り替える。
- 左パレットの最上位に **「画面」カテゴリ** を置く（画面A、画面を待つ、類似度、不明画面）。
- 初回導線は「① 取り込み → ② 画面を登録 → ③ 座標をクリックして確認 → ④ フロー化」のチェックリスト。
- 重要情報（現在の画面名・スコア・モード・保存状態）は常時ヘッダーまたはライブ上部に表示する。

## 8. フローとノードセット

### 8-1. 標準：状態フロー（Must）

画面上の「状態」を並べ、各状態に操作と遷移を持たせる。これが本製品の基本表現。

| 要素 | 内容 |
|---|---|
| 状態 `state` | 名前、対応する画面、開始条件（画面一致/類似度）、操作列、次状態、タイムアウト、失敗時 |
| 操作 `action` | クリック(x,y)、キー、キー長押し、キー離す、待つ |
| 遷移 `transition` | 次状態、条件（画面が変わった/物体が出た/時間経過）、待ち時間、リトライ |
| 不明画面 `unknown` | 待つ / 再試行 / 停止 / 回復フローへ |

例:

```
state: タイトル
  screen: title
  actions: [click(0.50, 0.80), wait_screen(home, timeout=10)]
  next: ホーム

state: ホーム
  screen: home
  actions: [click(0.30, 0.55), wait(1.0)]
  next: クエスト
```

### 8-2. 詳細ノード（条件を細かく書くとき）

| カテゴリ | ノード |
|---|---|
| 画面 | 画面が `screen_is`、画面を待つ `screen_wait`、画面が変わった `screen_changed`、類似度 `screen_score`、不明画面 `screen_unknown` |
| 見る | 物体 `objects`、自分 `me`、動き `motion`、時間 `clock` |
| 選ぶ | いちばん近い `nearest`、範囲内 `within`、IDで探す `by_id`、ロックオン `lock_on`、値を取り出す `field` |
| 判断 | 比べる `compare`、かつ `and`、または `or`、ではない `not`、数 `number`、計算 `math`、間隔 `cooldown`、保持 `hold_true` |
| 操作 | 座標クリック `click_xy`、物体クリック `click_object`、キー `key`、長押し `hold_key`、離す `release_key`、待つ `wait` |
| 便利 | 表示 `debug`、覚える `remember` |

### 8-3. レガシー（互換のみ・非表示）

`aim`、`click`、`click_at`、`dodge`、`strafe`、`search`、`path_toward`、`path_away`、`shot_spot`、`imitate`。
「上級者向け（非推奨）」を開いた場合だけ表示する。

## 16. 並列実行モデル（ここが難所ではない理由）

### 16-1. 方針：スレッドで並列化しない

ゲーム操作は 20fps の**1本のティック**で完結させる。毎ティック、

```
スナップショット取得
  → 各行動を評価（同じ世界を見る）
  → チャネルごとに1つに仲裁
  → 入力送出
```

とする。複数スレッドでキーを押すと「押す/離す」が競合し、再現性も失われる。
**並列に見える要求は、チャネル分離と1本のスコアに畳み込む。**

### 16-2. チャネル

| チャネル | 内容 | 競合の扱い |
|---|---|---|
| `move` | 方向キー（WASD）1組 | **1ティックに1つだけ**。優先度とスコアで選ぶ |
| `attack` | 攻撃キー / 対象クリック | 独立。移動と同時に実行できる |
| `click` | メニューのUIクリック | 画面遷移状態のときだけ。試合中は使わない |
| `log` | 判断理由・スコア | 競合なし（デバッグ用） |

この分離により「草むらへ移動しながら敵を撃つ」「ガスから逃げながら撃つ」が
**特別な並列処理なしで**成立する。

### 16-3. 優先度（プリエンプション）

| 優先度 | 行動 | いつ勝つか | チャネル |
|---|---|---|---|
| 4 | 生存（ガス回避） | 自分のクリアランス < `gas_danger` | move |
| 3 | 戦闘（攻撃） | 敵が射程内 | attack（move とは独立） |
| 2 | 位置取り（草むら） | 常時（既定の移動先） | move |
| 1 | 探索 | 草むらが見えない | move |
| 0 | 待機（草むら内） | 脅威なし | move = None |

- 高い優先度は**同じチャネル**だけを奪う。攻撃チャネルは奪われない。
- 奪うときも `min_dwell`（最小継続時間）と `switch_margin`（明確な差）を要求し、
  しきい値付近での往復（フリッカー）を防ぐ。

### 16-4. 「同時に満たす」ための1本のスコア

移動は「草むらへ行く」「ガスを避ける」「敵に近づきすぎない」「画面端を避ける」
を別々の行動として競わせるのではなく、**方向ごとの1つのスコア**に合算する。

```
score(方向 d) =  w_target  * 草むら方向との一致
               + w_safe    * 前方のガス余裕
               + w_escape  * ガスから離れる方向との一致
               - w_enemy   * 敵に近づく度合い
               - w_edge    * 画面端に近づく度合い
               + w_stuck   * 詰まり時の横方向との一致
```

16方向をサンプルし、最大の方向を8方向キーに変換する。これにより
「草むらへ向かいながらガスを避ける」が1回の決定で表現できる。

### 16-5. 競合が起きないことの保証

- 入力はティック末尾に**まとめて1回**だけ送る。
- モード変更・停止時は、その場で全キーを解放する（`hold` の残留を許さない）。
- 判断は同じスナップショットに対する純粋計算なので、録画リプレイで再現できる。

## 17. 行動アルゴリズム

### 17-1. 草むらの選択（目標決定）

各草むら `b` を次で採点し、最大を選ぶ。

```
score(b) = w_safe  * safety(b)      # ガスからの余裕（0〜1）
         + w_hide  * hide(b)        # 面積（大きいほど隠れやすい）
         + w_travel* travel(b)      # 自分からの近さ
         - w_enemy * threat(b)      # 敵に近すぎる草むらを避ける
```

- `safety(b)`: 草むらの中心からガスまでの距離。`gas_margin` 未満は大きく減点。
- `hide(b)`: 草むら面積 / 画面面積。上限 2%。
- `threat(b)`: `enemy_avoid` 以内の敵の近さの合計。
- **スティッキー**: 現在の目標がまだ有効なら、`switch_margin` 以上の差と
  `min_dwell` 経過があるまで乗り換えない（左右の草むらで往復しない）。

### 17-2. 移動（16方向のステアリング）

現在位置から 16方向をサンプルし、`lookahead` 先の安全性まで含めて採点する。

```
score(d) = w_target * dot(d, 目標方向)
         + w_safe   * safety(現在位置 + d * lookahead)
         + w_escape * dot(d, ガスから離れる方向)
         - w_enemy  * 敵に近づく度合い
         - w_edge   * 画面端に近づく度合い
         + w_stuck  * dot(d, 詰まり時の横方向)
```

- 最大の方向を移動ベクトルにし、入力層が8方向キーへ変換する。
- ガスに近いときは `safety` と `escape` が支配的になり、草むら方向より避難が勝つ。
- 草むらが目標でも、ガスが間にある場合は「回り込む方向」が選ばれる。
- 草むら内で脅威がないときは `move = None`（その場で待機）。

### 17-3. 毒ガスの扱い

- ガスは **マスク（True = ガス）** または領域ボックスで受け取る。
- マスクがある場合は距離変換で「ガスまでの距離」を毎フレーム計算する。
  - `clearance(x, y)` = 最寄りガスまでのピクセル距離
  - 自分・草むら・前方サンプル点の安全判定に使う。
- `clearance(自分) < gas_danger` になったら **生存モード（rotate）** に移行する。
- 目標草むらは `clearance >= gas_margin` のものだけを選ぶ。
  すべて危険なら「最も余裕のある草むら」または「ガスから離れる方向」へ逃げる。
- ガスはヒステリシス（入る/出るしきい値）と安定フレーム数で判定し、
  画面端の点滅でモードが往復しないようにする。

### 17-4. 攻撃（移動と独立）

- 自分から `enemy_range` 以内で最も近い敵を選ぶ。
- `attack_cooldown` が経過していれば攻撃を発火する（移動は継続）。
- 攻撃方式は設定で選ぶ:
  - `key`（既定）: 攻撃キーを押す
  - `click`: 敵の座標をクリック
  - `aim`: 照準キー/ドラッグ（レガシー。対象アプリが要求する場合のみ）
- 攻撃対象がいない、射程外、クールダウン中は何もしない。

### 17-5. 画面遷移と戦術レイヤーの接続

```
[画面認識] --(menu)--> [フロー: クリック/待機] --(match)--> [TacticalPolicy]
     ^                                                          |
     └──────────────── リザルト/ゲームオーバー ─────────────────┘
```

- 画面認識は毎ティック行い、`match` に入ったときだけ戦術レイヤーを有効化する。
- `match` から出たら `TacticalPolicy.reset()`（攻撃クールダウン・目標・詰まり状態を初期化）。
- メニュー中のクリックは正規化座標（0〜1）で保存し、解像度差を吸収する。

### 17-6. 振動（オシレーション）対策

| 現象 | 対策 | 設定 |
|---|---|---|
| 草むらA/Bを往復 | 目標のスティッキー | `switch_margin`, `min_dwell` |
| ガス境界でモードが往復 | 入る/出るしきい値、安定Nフレーム | `gas_danger`, ヒステリシス |
| 画面判定のちらつき | 連続一致フレーム数 | `enter_frames`, `exit_frames` |
| 攻撃の連打 | クールダウン | `attack_cooldown` |
| 微小な方向の震え | 方向サンプル + 停止条件 | `directions`, 待機判定 |
| 壁で押し続ける | 詰まり検知 → 横移動（左右交互） | `stuck_time`, `stuck_hold` |

### 17-7. 1ティックの処理（擬似コード）

```python
frame  = source.grab()
screen = recognizer.update(frame)          # 画面名・スコア・候補
if screen.name != "match":
    flow.step(screen)                      # クリック/待機/遷移
    return
dets    = detectors.detect(frame)
me, bushes, enemies, gas = build_world(dets)
decision = policy.tick(now, me, bushes, enemies, gas, w, h)
input.set_move(decision.move)              # 移動チャネル
if decision.attack:
    input.attack(decision.attack_target)   # 攻撃チャネル（独立）
publish(decision, screen, dets)            # UIへスコア・理由を送る
```

### 18-3. 既知の制限

- 画面テンプレートは複数枚に対応。大幅なUI変更には再登録が必要。
- 経路探索は「局所ステアリング + 詰まり時の横移動」であり、U字型の壁の奥にある草むらへは回り込めないことがある。
- ガスの色/領域検出の設定に依存する。誤検出が多いと過剰に回り込む。
- 攻撃の命中率は照準方式に依存する（デモのクリック攻撃は移動する敵に外れやすい）。
- 対象アプリの解像度・DPI・ウィンドウ構成に合わせた座標調整が必要。
- 画面名は名前でもIDでも一致するが、同名画面を複数登録すると名前一致は先に見つかったものになる。
- 注釈は矩形のみ（セグメンテーションのマスク注釈は未対応）。
- 学習はCPUだと時間がかかる。GPU推奨。初回はベースモデルのダウンロードがある。
- 学習中のゲーム操作はCPU/GPUを奪い合うため、学習は停止中に行うのが安全。

### 18-4. 対象アプリについて

このワークスペースには対象アプリの実体・画面キャプチャが含まれていなかったため、
付属デモ（Bush Arena）を対象アプリの代役として一気通貫で検証した。
対象アプリ環境では次の順で合わせる。

1. `python -m sightflow web --template brawl_like` でプロジェクトを作る
2. 設定でウィンドウ名・解像度（幅960に正規化）・検出ラベル（player / bush / enemy / gas）を合わせる
3. 画面タブで `title` `mode` `lobby` `match` `result` を登録する
4. ライブ画面で各ボタンの座標を取得し、`click_at` ノードへ入れる
5. 戦術ノードの攻撃方法（キー/クリック）と攻撃キーを合わせる
6. 見るだけで一致度・検出・ノード値を確認してから操作する
7. 検出が足りない物体は **学習タブ** でフレームを集め、箱を描き、YOLOを学習して
   `models/<name>.pt` を設定の「学習済みYOLO」で選ぶ






## 付録A. 画面類似の方式

| 方式 | 長所 | 短所 | 用途 |
|---|---|---|---|
| テンプレート一致（正規化相関） | 実装が簡単、高速、位置ずれに比較的強い | 解像度・UIスケール変更に弱い | 固定UIのボタン・ロゴ |
| SSIM | 構造の類似に強い、説明しやすい | 計算コスト、アニメに弱い | 画面全体の一致 |
| pHash | 解像度・軽微な変化に強い、超高速 | 細部の違いに弱い | 大まかな画面種別 |
| 特徴点（ORB/AKAZE） | 拡大縮小・回転に強い | 平坦な画面で弱い、誤対応 | ロゴ・アイコン |
| 色ヒストグラム | 照明変化に比較的強い | レイアウトを無視する | 画面の色調判定 |

推奨: 既定は **テンプレート一致（ROI付き）**。画面全体は補助的に **pHash**、複雑なUIは **特徴点** を選択可能にする。

## 付録B. 既存ノードとの対応

| 既存 | 本要件での扱い |
|---|---|
| `objects` / `nearest` / `within` / `by_id` / `lock_on` / `field` | 継続（検出の選択） |
| `compare` / `and` / `or` / `not` / `number` / `math` / `cooldown` / `hold_true` | 継続（判断） |
| `click_at` | `click_xy` に改名・拡張（座標ピッカー、ピクセル/正規化） |
| `key` | 継続。`hold_key` / `release_key` を追加 |
| `move_toward` / `move_away` / `move_dir` / `dodge` | レガシーまたは補助（方向キー押下に変換） |
| `aim` / `click` / `drag` | レガシー（非表示） |
| `path_*` / `shot_spot` / `strafe` / `search` / `imitate` | レガシー（feature の実験機能） |
| 画面系ノード | 新規（`screen_is` / `screen_wait` / `screen_score` など） |
| `wait` | 新規（秒数・画面待ち・物体待ち・タイムアウト） |

# 画面認識マクロの作り方

SightFlow の WebUI で、**「画面を見て → 決まった座標をクリック／キー入力 → 次の画面へ」** というマクロを作る手順です。
試合中は戦術ノードが草むら・敵・毒ガスを同時に扱います。

```
[画面: タイトル] → クリック(0.50, 0.80) → [画面: モード選択] → クリック → [画面: ロビー] → クリック
                                                                                    ↓
[画面: 試合] → 戦術ノード（草むらへ隠れる / 敵を撃つ / ガスから逃げる）
                                                                                    ↓
[画面: リザルト] → クリック（リトライ / 戻る）
```

## 1. まずデモで動かす

付属の Bush Arena（草むら・敵が実在するミニゲーム）で、戦術ノードだけを試せます。

```bash
python -m sightflow web demo/arena_macro.json
```

ブラウザで http://127.0.0.1:8765 を開き、**👁 見るだけ** → **● 操作する** の順に押します。
草むらへ入り、敵が近づくと撃ちます（デモはクリック攻撃）。

- ノードの下に `hide / in bush / 余裕∞px` など、今の判断が出ます
- ライブ画面に「画面」と一致度、検出した物体の一覧が出ます

## 2. 対象アプリ用のテンプレート

```bash
python -m sightflow web --template brawl_like
```

`templates/brawl_like.json` から `projects/brawl_like.json` が作られます（2回目以降は自分のコピーを使用）。
テンプレートには次のノードが配線済みです。

| 画面（名前で一致） | ノード | 操作 |
|---|---|---|
| `title` | 画面が → 画面座標をクリック | タイトルの開始ボタン |
| `mode` | 画面が → 画面座標をクリック | ソロモード |
| `lobby` | 画面が → 画面座標をクリック | 試合開始 |
| `match` | 画面が → 戦術 | 草むら / 敵 / ガス |
| `result` | 画面が → 画面座標をクリック | リトライ / 戻る |

**画面は名前で一致**します。画面タブで `title` `mode` `lobby` `match` `result` という名前で登録してください。
（登録時に自動で付くIDで選んでも構いません。）

## 3. 画面を登録する

1. **設定**タブで取り込み元を選ぶ（ウィンドウ / 画面範囲 / 動画）
   - ウィンドウ名の一部を入れると候補が出ます（例: `LDPlayer`）
2. **👁 見るだけ** を押す
3. **画面**タブで、今のフレームから登録する
   - 名前（例: `title`）
   - 方式: **テンプレート一致**（既定）/ pHash / SSIM
   - しきい値: 0.85 から開始
   - 安定フレーム: 入る2 / 出る2（一瞬のエフェクトで切り替わらない）
4. 画面を変えて、同じ手順で `mode` `lobby` `match` `result` を登録

### 方式の選び方

| 方式 | 向いている画面 | 注意 |
|---|---|---|
| テンプレート一致 | 固定UI・ボタン・ロゴ | 解像度やUIスケールが大きく変わると弱い |
| pHash | 画面全体のざっくり判定 | 細部の違いは苦手 |
| SSIM | 構図が同じ画面 | アニメーションに弱い |

- 一致度が足りないときは、しきい値を下げる／方式を変える／ROIで動く部分を除外する
- 同じ画面でも見た目が変わる場合（解像度・アニメ）は **＋テンプレート** で追加する
  （一致度は全テンプレートの最大値。最後の1枚は削除できません）
- 別画面と誤一致するときは、しきい値を上げる／ROIを狭める
- 画面タブの「いまの判定」に**上位候補**が出るので、どの画面と誤認しているか分かります
- ROIはプレビュー上を**ドラッグ**して指定できます（数値入力も可）

## 4. クリック座標を入れる

1. **ライブ画面**で、押したいボタンの上をクリック
2. `x=0.512, y=0.803` のような**割合**がコピーされます
3. キャンバスの **画面座標をクリック** ノードの `x` / `y` に入れる

- 0〜1は画面に対する割合、1より大きい値はピクセルとして扱われます
- ウィンドウサイズが変わっても割合なら追従します
- 同じ画面で複数のボタンを押す場合は、ノードを分けてください

## 5. 検出を合わせる（草むら・敵・ガス）

**設定**タブの検出器でラベルを作ります。色検出器なら HSV、YOLO-World なら英語のプロンプトです。

| ラベル | 例 | 用途 |
|---|---|---|
| `player` | 自分のHPバー（緑） | 距離・方向の基準（自分のラベル） |
| `bush` | 草むらの緑 | 隠れる場所 |
| `enemy` | 敵のHPバー（赤） | 攻撃対象 |
| `gas` | 毒ガスの紫/緑 | 危険地帯（無ければ空欄） |

- 草むらは**領域**として扱えます。「領域（色）」検出器（`region`）ならポリゴンで判定するため、内側にいるかが正確です
- ガスも領域で検出すると、ポリゴンから「ガスまでの距離」を計算し、安全マージンを判定できます
- 色の領域設定（HSV・最小面積）はプロジェクトJSONの `settings.detector.region` に書きます
- ラベル名は戦術ノードの設定と一致させてください

## 6. 戦術ノード

**操作 → 戦術（草むら/敵/ガス）** を置き、設定します。

| 設定 | 内容 |
|---|---|
| 草むらラベル | 例: `bush` |
| 敵ラベル | 例: `enemy` |
| ガスラベル | 例: `gas`（無ければ空） |
| 攻撃方法 | **キー**（既定）/ クリック |
| 攻撃キー | エミュレータの攻撃キー（例: `space`） |
| 攻撃射程(px) | この距離以内の敵を撃つ |
| 攻撃間隔(秒) | 連打を防ぐ |
| ガス余裕(px) | 草むらに求める安全マージン |
| 危険距離(px) | これよりガスに近いと避難を優先 |
| 優先度 | 他の移動ノードと競合したときの強さ |

**移動と攻撃は同時に動きます**（別チャネル）。停止して撃つ必要はありません。

## 7. 実行と確認

1. **👁 見るだけ** で1周させる
   - 画面タブの一致度 / 候補
   - 各ノードの値（`画面が`、`戦術` の `hide / in bush / 余裕120px`）
   - ライブ画面の検出一覧（ラベル・信頼度・距離）
2. 問題なければ **● 操作する**（確認ダイアログ）
3. 止めるときは **F12**（ゲームが前面でも効きます）

見るだけでは**キーもマウスも一切送りません**。停止・モード変更時は押していたキーを解放します。

## 8. しくみ（並列動作）

スレッドで同時に動かすのではなく、1ティックの中で**チャネルを分けて仲裁**します。

| チャネル | 内容 | 競合 |
|---|---|---|
| 移動 | WASD の方向1組 | 優先度が高い1つだけ |
| 攻撃 | 攻撃キー / クリック | 移動と独立（同時可） |
| UIクリック | メニューの座標クリック | 画面が一致している間だけ |

優先度は **ガス回避 > 攻撃 > 草むら > 探索**。
移動方向は16方向をサンプルし、次の合計が最大の方向を選びます。

```
行きたい方向 + ガスの余裕 + ガスから離れる + 敵を避ける - 画面端 + 詰まり時の横移動
```

そのため「草むらへ向かいながらガスを避ける」「隠れながら撃つ」が1回の判断で成立します。
目標の草むらは、安全さ・広さ・近さ・敵の脅威で採点し、**明確に良い候補が出るまで乗り換えません**（往復防止）。

## 9. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 画面が「不明」のまま | 見るだけになっているか。しきい値を下げる。ROIを広げる。方式を変える |
| 別画面と誤認する | しきい値を上げる。ROIを狭める。「いまの判定」の候補を見る |
| 画面がちらつく | 安定フレームの「入る/出る」を増やす。しきい値とヒステリシス |
| クリック位置がずれる | ライブ画面で座標を取り直す。ウィンドウのDPI/拡大率を確認 |
| 草むらに入らない | `bush` ラベルが検出されているか。戦術ノードのラベル名。優先度 |
| 敵を撃たない | 攻撃方法（キー/クリック）、攻撃キー、射程、`enemy` ラベル |
| ガスから逃げない | `gas` ラベル、危険距離、ガス余裕。ガスの色検出を確認 |
| 壁で止まる | 詰まり検知が横移動します。それでもだめなら優先度やマップの形状 |

## 10. 制限と次の拡張

- 画面テンプレートは複数枚に対応。大幅なUI変更は再登録が必要
- 草むら・ガスは領域（ポリゴン）に対応。セグメンテーションの**マスク注釈**は未対応
- 経路探索は局所ステアリング。複雑なU字の壁の奥へは回り込めないことがある
- 動画は一時停止・1フレーム送りで確認できます（ライブ画面のボタン）
- OCR（画面内の文字条件）は未実装
- 対象アプリの画面名・座標・色は環境ごとに調整が必要

## 11. 自分でラベルを付けてYOLOを育てる（学習タブ）

色やYOLO-Worldで見つけにくいものは、自分の画面でYOLOを学習させます。
**学習タブ**で「フレーム収集 → 箱を描く → 学習」まで完結します。

1. **👁 見るだけ** で対象の画面を出す
2. **学習**タブでデータセット名を確認（既定はプロジェクト名）
3. **今のフレームを保存** を押す（何枚か、敵・草むら・ガスが写る画面で）
   - **自動収集** も使えます。間隔（秒）を入れて「開始」→ 見るだけ／操作する中で一定間隔ごとに保存
4. フレームを選び、キャンバス上を**ドラッグして箱**を描く
   - 「次の箱のクラス」を選んでから描く
   - 箱は一覧からクラス変更・削除できる
   - **選択を自動ラベル** を押すと、今の検出器の結果を箱に変換する
5. **ラベルを保存**
6. **学習** でモデル（`yolo11n.pt` など）・epochs・imgsz・batch を決めて **学習を開始**
   - 進捗と mAP50 が表示されます（CPUでも小さいモデルなら動きます）
   - 完了すると `models/<データセット名>.pt` に保存
7. **設定 → 検出器 → 学習済みYOLO** で、そのモデルを選ぶ

### データの場所

```
datasets/<name>/
  images/train/*.jpg   images/val/*.jpg   # 5枚に1枚が val
  labels/train/*.txt   labels/val/*.txt   # class cx cy w h（0〜1）
  classes.json         data.yaml
```

- クラス順は `classes.json` に固定されるので、後から検出ラベルを変えても既存データの意味は変わりません
- 画像・データセット・学習結果（`runs/`）は `.gitignore` 対象です
- まずは100枚程度、画面・敵・草むらを満遍なく。誤検出のフレームも入れると丈夫になります
- 学習はGPU推奨。初回はベースモデルのダウンロードがあります

## 12. デモでの検証結果

Bush Arena（描画ピクセルのみ、色検出）で戦術ノードを実行:

| seed | 時間 | 草むら滞在率 | 初回到達 | 攻撃 | 撃破 | HP |
|---|---|---|---|---|---|---|
| 1 | 30s | 99% | 0.4s | 26 | 6 | 5 |
| 2 | 30s | 94% | 0.6s | 25 | 8 | 5 |

自動テスト: `pytest -q` で 94 件成功（画面類似・複数テンプレート・領域・注釈・学習・戦術・デモ結合を含む）。

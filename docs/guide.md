## 1. 準備と起動

必要なもの:

- Windows 10/11（ウィンドウの取り込みとキー操作は Windows 向けに作っています）
- Python 3.10 以上
- Node.js 18 以上（画面部分をビルドするときだけ）
- NVIDIA の GPU（なくても動きますが、YOLO-World がかなり遅くなります）

### 初回だけ

```bash
git clone https://github.com/aruiki/SightFlow-GameBot.git
cd SightFlow-GameBot

# 仮想環境は「短いパス」に作る（深いフォルダだと PyTorch が読み込めないことがあります）
python -m venv C:\Users\<you>\.venvs\sightflow
C:\Users\<you>\.venvs\sightflow\Scripts\activate

# GPU 版 PyTorch → そのほかの部品
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt

# 画面部分をビルド
cd webui
npm install
npm run build
cd ..
```

### 毎回の起動

```bash
C:\Users\<you>\.venvs\sightflow\Scripts\activate
python -m sightflow web
```

ブラウザで **http://127.0.0.1:8765** を開きます。最初は付属のデモ（`demo/arena_project.json`）が開きます。

自分用のプロジェクトを新しく作るときは、ファイル名を付けて起動します。ファイルがなければ空のプロジェクトが作られます。

```bash
python -m sightflow web projects/mygame.json
```

## 2. デモで動きを見る

画面は3つに分かれています。

| 場所 | 内容 |
|---|---|
| 左 | ノードの一覧。色ごとに分類されています |
| 中央 | ノードを置いて線でつなぐ場所（キャンバス） |
| 右 | **ライブ画面**（取り込んだ映像と検出結果）と **設定** |

上の真ん中にあるのがモードの切り替えです。

| モード | 動作 |
|---|---|
| ■ 停止 | 何もしない |
| 👁 見るだけ | 検出とノードの計算だけ行い、**キーやマウスは一切操作しない** |
| ● 操作する | 実際にキーとマウスを操作する。**F12** でいつでも停止 |

デモでは「● 操作する」を押してみてください（デモは画面の中のゲームなので、あなたのキーやマウスは動きません）。

- ライブ画面に、検出された物体の枠と **`ラベル #ID`**（例: `enemy #20`）が表示されます。
  同じ物体はずっと同じ ID になります。
- 白い矢印が「今どちらへ移動しようとしているか」、黄色の矢印が「撃った方向」です。
- 中央の各ノードの下に **今の値** が出ます（「2個」「enemy#20 85px」「true」など）。
- 実際に操作を出したノードは **黄色く光ります**。
- 「物体」ノードをクリックで選ぶと、ライブ画面でそのラベル以外が薄くなります。

## 3. 考え方：見る → 選ぶ → 判断 → 操作

ノードは左から右へ流れるように並べます。

```
 見る（青）        選ぶ（紫）        判断（橙）           操作（赤）
[物体: enemy] → [いちばん近い] → [値を取り出す: 距離] → [比べる: < 300] → [狙って撃つ]
                       └──────────────── 対象 ──────────────────────────────┘
```

- **見る**: 画面から情報を取り出す（検出された物体、自分の位置、動き、時間）
- **選ぶ**: 物体のリストから1つを選ぶ、範囲で絞る、距離などの数値を取り出す
- **判断**: 数を比べる、かつ/または、一定間隔にする
- **操作**: 移動する、狙って撃つ、クリックする、キーを押す

### 線の色＝データの種類

| 色 | 種類 | 例 |
|---|---|---|
| 紫 | リスト | 見えている敵ぜんぶ |
| 青 | 物体 | いちばん近い敵 1体 |
| 緑 | 数 | 距離 250px |
| 黄 | はい/いいえ | 「射程内か」 |

違う色どうしは**つながりません**。つながらないときは、間に変換するノードが必要です
（物体 → 数 なら「値を取り出す」、数 → はい/いいえ なら「比べる」）。

### 操作ノードの「実行」

操作ノードには **実行**（はい/いいえ）の入力があります。

- つないだ場合: 「はい」のときだけ動く
- つながない場合: いつも動く

### 移動がぶつかったとき

「近づく」「離れる」「方向に移動」「横によける」が同時に動こうとしたら、**優先度が大きいもの**が勝ちます。
負けたノードには「（優先度で負け）」と表示されます。

> 例: 草むらへ近づく（優先度1）、コインへ近づく（2）、敵から離れる（3）、壁から横によける（9）
> → ふだんは草むら、敵が遠ければコイン、近すぎたら逃げる、引っかかったらよける、になります。

## 4. 最初のボットを作る

デモの画面で、「敵を狙って撃ち、近すぎたら離れる」ボットを一から作ってみます。

### 4-1. まっさらにする

上の **「新規」** を押します（ノードがすべて消えます。デモの元の状態は
`git checkout demo/arena_project.json` でいつでも戻せます）。

ノードを置くには、左の一覧から **キャンバスへドラッグ** するか、**ダブルクリック** します。
線は、ノードの右側の点（出力）から左側の点（入力）へドラッグしてつなぎます。
ノードや線を消すときは、選んでから Delete キーを押します。

### 4-2. 敵に近づく

1. 「物体」を置き、設定の **ラベル** を `enemy` にする
2. 「いちばん近い」を置き、物体の **リスト** → いちばん近いの **リスト** をつなぐ
3. 「近づく」を置き、いちばん近いの **物体** → 近づくの **対象** をつなぐ

「● 操作する」を押すと、青い自分が敵に向かって動きます。

### 4-3. 射程に入ったら撃つ

4. 「値を取り出す」を置き、いちばん近いの **物体** → **物体** をつなぐ（項目は `distance` のまま）
5. 「比べる」を置き、値を取り出すの **値** → 比べるの **a** をつなぐ。比較 `<`、b `300`
6. 「狙って撃つ」を置き、比べるの **結果** → **実行**、いちばん近いの **物体** → **対象** をつなぐ

比べるノードに `true` が出ている間だけ、狙って撃つが光ります。

### 4-4. 近すぎたら離れる

7. 「比べる」をもう1つ置き、値 → a、比較 `<`、b `80`
8. 「離れる」を置き、その結果 → **実行**、いちばん近い → **対象**
9. 離れるの **優先度** を、近づくより大きく（例: 近づく 1、離れる 3）

これで「近づく → 射程に入ったら撃つ → 近すぎたら下がる」になります。

### 4-5. 中身を確かめる

途中の値が分からなくなったら **「表示」** ノードをつなぐと、流れている中身がノード上に出ます
（リストなら `3個: enemy#4, enemy#7, …`）。

変更は自動保存されます（右上が「保存済み」になります）。
ほかの人に渡すときは **「書き出し」** でJSONファイルにでき、**「読み込み」** で開けます。

## 5. 自分のゲームで使う

### 5-1. 取り込み元を選ぶ

右の **設定** タブを開きます。

- **ウィンドウ**: ゲームやエミュレータのウィンドウ名の一部を入れます。入力欄をクリックすると、開いているウィンドウの候補が出ます
- **画面の範囲**: `左, 上, 幅, 高さ` をピクセルで指定します
- **動画ファイル**: 録画したプレイ動画で、まず検出だけ確かめたいときに便利です

### 5-2. 何を検出するか決める（YOLO-World）

検出器は **YOLO-World** を選びます。表に「ラベル」と「探すもの」を書きます。

| ラベル（ノードで使う名前） | 探すもの（英語で説明） |
|---|---|
| player | blue character with green health bar |
| enemy | character with red health bar |
| chest | wooden treasure chest |

コツ:

- 「探すもの」は**英語**で、**見た目**を具体的に書きます（色・形・素材）。ゲーム内の固有名詞は通じません
- まず「見るだけ」にして、ライブ画面で枠が付くか確かめます。付かないときは言い換える、**信頼度のしきい値**を下げる、**モデル**を M / L に上げる
- 小さい物体が多いゲームは、**入力サイズ**を 960 や 1280 にすると拾いやすくなります（重くなります）
- 誤検出が多いときは、しきい値を上げます

> YOLO-World は写実的な映像ほど得意で、デフォルメされたキャラクターは苦手なことがあります。
> 精度が足りない場合は、ゲームの画面で YOLO を学習させ、検出器を **学習済みYOLO** にして `best.pt` を指定するのが確実です。

### 5-3. 自分を決める

**自分のラベル** に、操作しているキャラのラベル（例: `player`）を選びます。
距離や方向はすべて「自分から見て」計算されます。自分が見つからないときは画面の中央が基準になります。

### 5-4. 操作のしかたを合わせる

- **移動キー**: ゲーム（エミュレータ）のキー割り当てに合わせます（既定は W/S/A/D）
- **狙って撃つ** の「ボタンx/y」: タッチ操作の攻撃ボタンの位置です。ライブ画面でボタンの位置を**クリックすると座標がコピー**されるので、それを入れます（0〜1 の割合）
- キーで攻撃するゲームなら、「狙って撃つ」の代わりに「キーを押す」を使います

### 5-5. 動かす

1. **「見るだけ」**: キーもマウスも動かないので、安全に判断の流れを確かめられます。ノードが思った通りに光るかを見ます
2. **「● 操作する」**: 確認が出たら開始します。止めるときは **F12**（ゲームが前面にあっても効きます）

> オンラインゲームの多くは、対戦相手がボットのモードであっても、自動操作を規約で禁止しています。
> アカウント停止の危険があるので、自作ゲーム・オフラインゲーム・許可された環境で使ってください。

## 5.5 コードなしで作る近道：記録と切り取り

### 操作を記録して再生する（FRep 風）
1. 設定で取り込み元（ゲームのウィンドウ）を選ぶ
2. 上部の **● 記録** を押し、ゲーム画面でいつもどおりクリック・キー入力する
3. 終わったら **F12**（または「■ 記録終了」）
4. キャンバスに **記録した操作** ノードができます。各行の「秒後」「クリック位置」「キー」はその場で直せます
5. 「繰り返し」を **ずっと** にすると、実行が はい の間くり返します。実行に「物体」ノードの「ある」をつなぐと「○○が見えたら再生」になります

ゲーム画面の外（SightFlow のブラウザなど）でのクリックは記録されません。

### 画面の一部を切り取って探す
1. 「見るだけ」でライブ画面を出す
2. ライブ画面の上の **✂ 画像を切り取って探す** を押し、探したいボタンやアイコンをドラッグで囲む
3. 名前を付けて「登録」。同じラベルの **物体** ノードが自動で置かれます
4. 見つかりにくい／誤検出が多いときは、設定タブの「切り取った画像」で **一致度** を調整します

学習や英語の説明は要りません。YOLO-World や色の検出と同時に使えます（検出器を「画像だけ」にすると切り取り画像だけで動きます）。

## 6. よく使う組み立て方（レシピ）

### 同じ敵を追い続ける（ロックオン）

「いちばん近い」は毎フレーム選び直すので、敵が2体いると狙いがふらつきます。
**「ロックオン」** を使うと、一度選んだ敵を追跡 ID で追い続けます。

```
[物体: enemy] → [ロックオン] → 物体 → [狙って撃つ]
```

見失っても「見失い猶予」の秒数は待ち、それを過ぎたら一番近い敵に乗り換えます。

### 壁に引っかかったら横によける

```
[動き] → 引っかかり → [しばらく続ける: 0.6秒] → 実行 → [横によける: 優先度 9]
```

壁を検出していなくても、「移動しようとしているのに動けていない」ことから引っかかりを判断します。
画面がキャラを追いかけるタイプ（カメラ追従）のゲームでも使えます。

### 一定間隔でキーを押す

```
[比べる: 何かの条件] → [間隔をあける: 3秒] → 実行 → [キーを押す: e]
```

「キーを押す」自体にも「間隔」がありますが、条件と組み合わせるときは「間隔をあける」を挟むと分かりやすくなります。

### ゲームオーバー画面でボタンを押す

ゲームオーバー画面の特徴をラベルにして（例: `retry` = `retry button`）、

```
[物体: retry] → ある → 実行 → [ここをクリック]   （または いちばん近い → [クリック]）
```

### 敵が何体以上なら逃げる

```
[物体: enemy] → [範囲内: 300] → 数 → [比べる: >= 3] → 実行 → [離れる]
```

## 7. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| ライブ画面に何も出ない | モードが「停止」になっていないか。右上が「準備OK」か（「読み込み中」なら待つ。初回はモデルのダウンロードがあります） |
| 「エラー」と出る | 赤い帯のメッセージを読む。ウィンドウ名が見つからない、動画のパスが違う、など |
| 枠が付かない | 5-2 のコツを試す。動画ファイルで先に確かめると早いです |
| ノードの下に「⚠」 | そのノードでエラー。マウスを乗せると詳細が出ます |
| 線がつながらない | データの種類（線の色）が違う。間に変換ノードを入れる |
| 「ループしている配線があります」 | 出力を自分の前のノードに戻している。ループはできません |
| 移動しない | 「操作する」になっているか。移動ノードが「優先度で負け」ていないか。移動キーの設定 |
| ゲームがキー入力を受け付けない | ゲームのウィンドウを前面にする。管理者権限で動くゲームは、SightFlow も管理者権限で起動する必要があることがあります |
| とても遅い | GPU 版 PyTorch が入っているか（`python -c "import torch; print(torch.cuda.is_available())"` が True）。モデルを S に、入力サイズを小さく |
| PyTorch の DLL が読み込めない | 仮想環境を短いパスに作り直す（1 を参照） |
